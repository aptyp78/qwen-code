# Слияние с оригиналом

Самая опасная рутина форка. Оригинал даёт ~254 коммита в неделю; ошибка здесь
стоит дороже любой другой.

## Жёсткие запреты

- **Никогда `rebase`.** Merge фиксирует разрешение конфликта один раз; rebase
  заставляет переразрешать его каждый цикл и ломает вычисление общей базы, на
  котором стоит вся проверка границы.
- **Никогда `--strategy=ours`, пакетный `checkout --theirs`, «упростим,
  выкинем нашу правку».**
- **Никогда не пушить теги upstream в origin** — это запустит чужую публикацию
  образов от имени владельца.
- Кнопка «Sync fork» в вебе GitHub запрещена.

## Порядок

1. Дерево чистое, ветка `dev`. Обновить карту горячих файлов:
   `node scripts/aso/cli.js heat`
2. `git fetch upstream --tags`
3. Выбрать цель: последний стабильный тег `vX.Y.Z` (не `-nightly`, не
   `-preview`), которому **не меньше пяти дней** — оригинал успевает выкатить
   исправления:
   `git tag -l 'v*' --sort=-creatordate --format='%(creatordate:short) %(refname:short)' | grep -Ev 'nightly|preview' | head -5`
4. Зеркалим: `git branch -f main <тег>`
5. Ветка слияния: `git switch -c sync/<версия> dev`, затем `git merge <тег>`
6. **Конфликты.** Файл, которого нет в `aso/intrusions.json`, конфликтовать не
   должен. Если конфликтует — значит реестр врёт: `git merge --abort`,
   остановиться и доложить владельцу. Это не задача на разбор руками.
   `package-lock.json` — взять версию upstream и пересоздать:
   `git checkout --theirs package-lock.json && npm install --package-lock-only`
7. Проверки: `node scripts/aso/cli.js check` и `drift`, затем полная сборка
   `npm run build && npm run typecheck` под Node 22.
8. Собрать канал и прогнать дым:
   `node scripts/aso/release.js build && sh scripts/aso/smoke.sh edge`
9. Записать итог в `aso/UPSTREAM-LOG.md`: дата, версия, сколько конфликтов, что
   решили, что сломалось. Это единственная память между сессиями агентов о том,
   как разрешались конфликты.
10. Слить `sync/<версия>` в `dev` **только merge**, без fast-forward.

## Когда останавливаться

Больше 20 конфликтующих файлов или больше четырёх часов работы — это не повод
для героизма, а сигнал деэскалации:

1. `git merge --abort`, слить промежуточный релиз вместо последнего — конфликты
   разбиваются на порции, а `rerere` накапливает разрешения.
2. Наложить наш оверлей поверх чистого upstream заново — он мал по построению.
3. В пределе пересобрать форк с нуля за день. Это возможно ровно потому, что
   функциональных вторжений ноль или единицы.
