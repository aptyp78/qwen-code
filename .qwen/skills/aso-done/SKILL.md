# Прежде чем сказать «готово»

## Проверяет машина

```
node scripts/aso/cli.js check     # граница цела
node scripts/aso/cli.js drift     # реестр совпадает с реальностью
```

Если изменения трогают `packages/**` — дополнительно сборка и типы под Node 22:

```
PATH="$HOME/.nvm/versions/node/v22.23.0/bin:$PATH" npm run build && npm run typecheck
```

Если изменения лежат только в `aso/**` и `.qwen/**`, ни сборка, ни тесты не
нужны: там нечему ломаться в продукте.

## Не проверяет никто, кроме тебя

1. **Изменение видимого поведения запущено вживую**, и вывод приложен к докладу.
   Не «тесты зелёные», а «вот что произошло». Для проверки есть канал `qqx`.
2. **Раздел «Что изменится для тебя»** — три строки человеческим языком и одна
   команда, которой владелец может убедиться сам. Он оценивает по смыслу, а не
   по коду, и без этого раздела оценить не может.
3. **Решение, ограничивающее будущую работу**, записано в `aso/DECISIONS.md`:
   дата, решение, почему. Пять строк, не журнал работ.

## Если ворота красные

Не обходи их. `git commit --no-verify` запрещён и отклоняется отдельно: именно
хуки удерживают границу форка. Красные ворота — это либо настоящая ошибка, либо
неточность в самих правилах; во втором случае правка правил идёт отдельным
изменением и с согласия владельца.
