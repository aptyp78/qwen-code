# Правила форка

Это долгоживущий форк `QwenLM/qwen-code`, а не сам qwen-code. Продукт боевой:
владелец работает им каждый день. Правила ниже обязательны и проверяются
машиной — их нарушение отклоняется на `git commit` и `git push`.

**Первое действие в новой сессии:**

```
node scripts/aso/cli.js brief
```

---

## Закон нулевого касания

**Наш код не смешивается с их кодом.** Оригинал выпускает ~254 коммита в неделю
и релиз каждые два дня. Любая наша правка в их файле будет конфликтовать почти
при каждом обновлении, и через полгода форк станет неподдерживаемым. Поэтому
задача решается на минимально возможном уровне.

| Тир    | Механика                                                                       | Цена при слиянии            |
| ------ | ------------------------------------------------------------------------------ | --------------------------- |
| **T0** | `settings.json`: свои модели (`modelProviders`), MCP-серверы, хуки, разрешения | ноль                        |
| **T1** | расширение `aso/extension/` — команды, скиллы, субагенты, хуки, контекст       | ноль                        |
| **T2** | свой пакет `aso/packages/<имя>/`, доступ через MCP или их SDK                  | ноль                        |
| **T3** | `patches/<пакет>.patch` — правка чужой зависимости                             | только по этой зависимости  |
| **T4** | правка файла upstream внутри `FORK:BEGIN`/`FORK:END`                           | конфликт при каждом слиянии |

Подъём на следующий тир требует письменного обоснования: чем именно не подошёл
предыдущий. Обоснование хранится в `aso/intrusions.json` и одобряется владельцем.

Три следствия, выведенные из замеров частоты правок:

- Свои пакеты — **не** в `packages/`: там глоб `packages/*` в npm-workspaces, и
  наш пакет попадёт в чужую сборку и матрицы CI.
- Свои настройки — **не** в `packages/cli/src/config/settingsSchema.ts`
  (131 правка за квартал, самый дорогой возможный T4), а в своём файле, который
  читает наше расширение.
- Версию в корневом `package.json` **не трогаем никогда** (77 правок за
  квартал): наша идентичность появляется только при упаковке артефакта.

## Зоны

Границы описаны в `aso/ownership.json`, актуальный расклад покажет `brief`.

| Зона               | Что можно                                                                                                   |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| `aso-owned`        | свободно: `aso/**`, `.qwen/{rules,skills,agents,commands}/**`, `.claude/**`, `.github/workflows/aso-*`      |
| `cold-zones`       | новые файлы свободно: холодные подсистемы ядра (`prompts`, `mcp`, `providers`, `models`, `hooks`, `memory`) |
| `upstream-hot`     | только по регистрации и только внутри якорей: 82 файла с 40+ касаниями за квартал                           |
| `upstream-default` | только по регистрации                                                                                       |
| `aso-meta`         | **нельзя**: файлы, описывающие сами правила                                                                 |

Список горячих файлов не пишется руками — `node scripts/aso/cli.js heat`
пересчитывает его из истории оригинала. Рукописный список врёт через квартал.

## Ветки

| Ветка    | Роль                                        | Правило                                           |
| -------- | ------------------------------------------- | ------------------------------------------------- |
| `main`   | точное зеркало upstream                     | коммитить запрещено; только перемотка на upstream |
| `dev`    | наш транк, ветка по умолчанию               | работа идёт в `feat/*`, `fix/*`, `sync/*` от неё  |
| `stable` | из чего собран рабочий инструмент владельца | только промоушен, только перемоткой               |

## Что запрещено всегда

- Править `aso/ownership.json`, `aso/intrusions.json`, `scripts/aso/**`,
  `.husky/**`, `AGENTS.md`, `CLAUDE.md`, `.gitignore`, `.gitattributes`.
  Это зона `aso-meta`: агент, упёршийся в ворота, не должен иметь возможности
  отредактировать ворота.
- Коммитить в `main` и `stable`.
- `git push --force`, `git commit --no-verify`, `git rebase` на upstream.
- Кнопка «Sync fork» в веб-интерфейсе GitHub — она умеет форс-ресетнуть ветку.
- Пушить теги upstream в наш репозиторий — это запустит чужую публикацию
  образов от имени владельца.
- Менять политику тем же изменением, что и код: сначала правила, потом правка.

## Слияние с оригиналом

Раз в две недели, на последний стабильный тег `vX.Y.Z` (не nightly, не preview),
которому не меньше пяти дней — оригинал успевает выкатить исправления.

**Только `merge`, никогда `rebase`.** Merge фиксирует разрешение конфликта один
раз; rebase заставляет переразрешать его каждый цикл и ломает вычисление общей
базы, на котором стоит вся проверка границы.

Конфликты разрешаются **только внутри якорей**. Конфликт в файле, которого нет
в реестре, означает, что реестр врёт: остановиться и доложить, а не разруливать
руками.

## Перед тем как сказать «готово»

```
node scripts/aso/cli.js check     # граница цела
node scripts/aso/cli.js drift     # реестр совпадает с реальностью
```

Плюс два пункта, которые машина проверить не может:

1. Изменение видимого поведения **запущено вживую**, и вывод приложен. Не
   «тесты зелёные», а «вот что произошло».
2. Написан раздел **«Что изменится для тебя»** — три строки человеческим языком
   и одна команда для проверки. Владелец оценивает по смыслу, а не по коду.

## Стоимость проверок

Полный `npm run preflight` — десятки минут, в повседневности он не запускается.
При соблюдении границы изменения лежат в `aso/**`, тесты и проверка типов не
нужны вовсе, и ворота проходят за секунду. Дисциплина делает проверку
бесплатной, нарушение — дорогим.

## Конвенции кода

Наследуются от оригинала без изменений, см. `AGENTS.md`: ESM, строгий
TypeScript, без `any`, без `console`, `kebab-case.ts` в `core` и `cli`,
`PascalCase.tsx` для компонентов, тесты рядом с исходником, Node 22.

Сообщения коммитов — Conventional Commits с обязательным трейлером
`Agent: <кто>`.
