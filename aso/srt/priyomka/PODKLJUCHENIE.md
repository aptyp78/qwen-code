# Подключение приёмки — решение владельца

Хуки живут в `.qwen/settings.json`, а этот файл — зона `aso-meta`: в нём же
сидит сторож границы форка. Агент его не правит, и это правильно: агент,
упёршийся в ворота, не должен иметь возможности отредактировать ворота.

Проверено на живом случае: попытка подключить приёмку была отклонена
`pre-commit` на том самом агенте, который приёмку и писал.

## Что включить

Два хука. Паспорт пишется на старте субагента, приёмка — на завершении.

```json
"SubagentStart": [
  { "hooks": [ { "type": "command", "name": "aso-pasport",
    "command": "node $QWEN_PROJECT_DIR/.qwen/hooks/pasport.mjs", "timeout": 5000 } ] }
],
"SubagentStop": [
  { "hooks": [ { "type": "command", "name": "aso-priyomka",
    "command": "node $QWEN_PROJECT_DIR/.qwen/hooks/priyomka.mjs", "timeout": 10000 } ] }
]
```

## Одной командой

```
ASO_META=1 node aso/srt/priyomka/podkljuchit.mjs
git add .qwen/settings.json
ASO_META=1 git commit -m "chore(srt): подключить паспорт и приёмку

Fork-Meta: приёмка продукта включается в ежедневный инструмент"
```

Скрипт добавляет только недостающее и не трогает остальные хуки; повторный
запуск ничего не меняет.

## Что это стоит

Позиция без поля `priyomka` проходит без вмешательства — цена ноль. Правило
`границаМатериала` стоит одного лишнего оборота, `цитатаИзМатериала` — до трёх.
Выключить не трогая настроек: `ASO_PRIYOMKA=off`.
