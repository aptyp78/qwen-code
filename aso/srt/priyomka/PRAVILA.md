# Обязанность объявляет позиция

Правило приёмки называет сама позиция — полем `priyomka` в своём определении:

```markdown
---
name: svodchik
description: Сводит факты из файлов.
tools: read_file
priyomka: границаМатериала
---
```

**Позиция без объявленного правила проходит без вмешательства.** Это условие,
без которого приёмку нельзя включать: требовать «назови, чего не нашёл» от
позиции, которая переписывает функцию, бессмысленно и мешает каждый раз.

## Наличные правила

| Правило             | Что требует                               | Чем проверяется                                                                |
| ------------------- | ----------------------------------------- | ------------------------------------------------------------------------------ |
| `границаМатериала`  | назвать факт, который искал и не нашёл    | названное сверяется с прочитанным: если оно там есть, обязанность не выполнена |
| `цитатаИзМатериала` | подтвердить сказанное дословной выдержкой | выдержка ищется в прочитанном дословно                                         |
| `формаОтвета`       | предъявить продукт в объявленной форме    | ищутся метки, названные позицией в поле `metki`                                |

**Обязанностей может быть несколько:** `priyomka: цитатаИзМатериала, формаОтвета`.
Все проверяются за один оборот, причины уходят позиции вместе. Одиночное имя
работает как раньше.

Метки правило знать не может — у выделителя одни, у сводчика другие. Поэтому их
называет сама позиция:

```markdown
priyomka: цитатаИзМатериала, формаОтвета
metki: КЕЙС, КОМПОНЕНТ, ПРИЗНАК, СОСЕД, ЧТО, ЦИТАТА
```

Правило появилось потому, что форму не проверял никто, и модель три прогона
подряд писала `ЦИТАЯ` вместо `ЦИТАТА`. Разбор продукта по меткам на этом
ломается, а прежде это обходили регулярным выражением в скрипте разбора — то
есть чинили в конвейере, а не в позиции.

Неизвестное имя правила не блокирует работу — записывается в журнал как
пропуск, чтобы опечатка была видна.

## Живой прогон 27.08.2026, локальная gemma4:12b

| Позиция    | Правило           | Оборотов | Итог                             |
| ---------- | ----------------- | -------- | -------------------------------- |
| `prostoy`  | нет               | 0        | приёмка не вмешалась             |
| `svodchik` | границаМатериала  | 2        | назвал «срок завершения проекта» |
| `citator`  | цитатаИзМатериала | 4        | привёл дословную выдержку        |

**Что поймало правило цитаты во втором обороте.** Агент закавычил собственную
формулировку — «Текущий статус проекта: в работе.» — и предъявил её как
выдержку. В материале написано «Статус: в работе». Это подделка не факта, а
источника, и сверка её поймала.

## Цена

Позиция без правила — ноль. `границаМатериала` — один лишний оборот.
`цитатаИзМатериала` — до трёх лишних оборотов, около десяти секунд на локальной
модели. Строгость стоит оборотов, и это надо учитывать при назначении правила.

## Отказ приёмки и его обнаружение

Приёмка не должна ломать работу: при сломанном или отсутствующем хуке агент
продолжает. Проверено намеренной поломкой — работа прошла в обоих случаях.

Но отсюда следует опасное: **отказ приёмки неотличим от её отсутствия**. Ответ
проходит так, будто правила не было, и следа не остаётся.

Обнаружить это самой приёмкой нельзя — она же и сломана. Обнаруживается
встречной записью: паспорт пишется **до** работы и знает, какое правило
объявлено; след приёмки пишется **после** и знает, что она отработала.
Расхождение между двумя независимыми следами и есть сигнал.

```
node .qwen/hooks/svodka.mjs [каталог проекта]
```

**Оба следа лежат в одном каталоге** — `agent-<id>.pasport.json` и
`agent-<id>.priyomka.jsonl` рядом. Это условие работоспособности, а не
удобство. Первая редакция клала журнал приёмки рядом с самим хуком, а паспорта
брала из общего `~/.qwen/projects/**`. Хук копируется вместе с проектом, поэтому
журналов заводится по одному на копию, и сверка объявила «приёмка не
отработала» на всех восьми позициях при одном настоящем отказе. Разбор:
`aso/srt/sledy/2026-08-27/SPRAVKA.md`.

**Обязанность считается по позиции, а не по машине.** Паспорт пишет поле
`правилоПриёмки` — то самое, что позиция объявила. Прежняя редакция считала по
списку хуков из настроек и записывала в нарушители `prostoy`, который правила не
объявлял и справедливо прошёл без вмешательства.

Сверка различает четыре состояния:

| Знак | Что значит                                                                   |
| ---- | ---------------------------------------------------------------------------- |
| `✓`  | правило объявлено, след есть — видно число оборотов и чем кончилось          |
| `✗`  | правило объявлено, следа нет — приёмка отказала молча                        |
| `?`  | паспорт прежней редакции, поля нет — сверять нечем, и молчать об этом нельзя |
| —    | позиция правила не объявляла, приёмке нечего было делать                     |

Живая проверка на трёх случаях сразу: приёмка отработала, приёмка выключена
имитацией отказа, позиция без правила.

```
✓ svodchik  svodchik-ПРОВЕРКА-1  границаМатериала  принято, оборотов: 1
✗ svodchik  svodchik-ПРОВЕРКА-2  границаМатериала  приёмка не отработала

обязаны приёмкой: 2, без следа приёмки: 1, без объявленного правила: 1
```

Журнал рядом с хуком остался — но только для чтения глазами. Сверка его не
читает: по нему сверять нельзя.

## Когда сверять не с чем

Пустой материал означает не «всё сошлось», а «сверить не с чем». Приёмка
отклоняет и различает два положения дел:

| Что случилось        | Кто отвечает             | Что уходит позиции                         |
| -------------------- | ------------------------ | ------------------------------------------ |
| журнал есть, но пуст | позиция: не звала орудий | «прочитай материал, не опирайся на память» |
| журнала нет вовсе    | конструкция, не позиция  | «журнал недоступен, сверить не с чем»      |

В след ложится `НЕ-СВЕРЕНО`, и сверка показывает такую позицию как `✗` с
пометкой «сверить было не с чем» — не как благополучие.

До 28.08 правило `границаМатериала` в этом случае **принимало**: при пустом
материале все названные слова отсутствуют, значит заявление верно. В след
ложилось «отсутствуют в материале: …» о материале, которого не читали. Защита
была написана, но стояла во второй половине условия и не срабатывала никогда.
Нашла вторая сессия набором проверок; воспроизведено независимо.

Отклонять безопасно: блокирующие обороты ограничены продуктом, по умолчанию
восемь.

## Набор проверок

Десять кейсов, без вызова модели, секунды на прогон. Живёт у второй сессии —
это её предмет; две копии одного средства разойдутся редакциями.

```
python3 .worktrees/playbook/aso/evals/priyomka.py --hooks $PWD/.qwen/hooks
```

## Выключатель

```
ASO_PRIYOMKA=off
```

Снимает приёмку, не трогая настройки. Нужен на случай, когда она мешает
срочной работе: править `settings.json` под нагрузкой — верный способ
оставить его сломанным.
